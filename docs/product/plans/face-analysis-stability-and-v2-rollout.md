# Face Analysis 稳定性与 2.0 渐进式演进计划

**状态：** Active — 当前执行基线
**日期：** 2026-08-11
**范围：** 已上线的付费 Face Analysis 转化链路，以及独立验证的 Face Analysis 2.0

## 1. 决策

Face Analysis 已是 Credits Pack、解锁报告、Top Picks Try-On 的关键转化节点。不得把未验证的架构、模型融合逻辑或供应商行为直接替换进当前付费路径。

后续工作分为两条并行但隔离的轨道：

1. **当前版本稳定性轨道：** 仅修复重复调用、超时、幂等和可观测性；不改变用户已经熟悉的“照片 + VLM 深度报告”产品语义。
2. **Face Analysis 2.0 验证轨道：** 在独立版本、独立数据和 feature flag 下验证“landmark 几何 + VLM 视觉审阅 + 融合报告”。未达到替换门槛前，不接管生产付费流量。

免费 Face Shape Detector 仍保持本地处理、无上传、无 Gemini 的定位；本计划讨论的是登录后的付费 Face Analysis。

## 2. 当前版本：分批稳定性优化

### Batch 1 — 防止重复处理与无界超时

目标是让一次用户动作最多对应一个 FaceAnalysisTask，并避免不确定结果的重复人脸提交。

- 对网络中断和本地 AbortError/timeout 不自动重新提交同一张图片；只有收到明确且安全的供应商瞬态错误时才允许受总时限约束的一次重试。
- 为 FaceAnalysisTask 增加持久化的 `clientSubmissionId`，并以 `(userId, clientSubmissionId)` 作为唯一幂等键。
- 前端为同一次分析动作稳定复用同一个 `clientSubmissionId`；用户主动“重新分析”才生成新 ID。
- 服务端遇到相同幂等键时返回已存在任务，而不是再上传图片或调用供应商。
- 让单次请求的总时间预算严格小于部署函数时限；不得出现“重试预算大于 route maxDuration”的配置。

验收：同一幂等键在并发、浏览器重试和刷新恢复场景下只创建一个任务；每个任务的外部调用次数可审计。

### Batch 2 — 可观测性与延迟基线

目标是区分本地处理、上传、供应商排队和模型响应，避免把所有慢请求归因于模型。

- 在 Axiom 日志中贯穿 `taskId`、`clientSubmissionId`、请求关联 ID、attempt、模型、图片传输方式。
- 记录 landmark、Blob 上传、任务创建、供应商首字节/完整响应、解析、数据库写入和端到端耗时。
- 建立仪表盘：完成率、超时率、P50/P95 报告耗时、每任务外部调用数、供应商错误类型、重复任务率。
- 为用户可见的失败定义一致错误码与恢复动作；不可把“可能已执行”的超时伪装成安全重试。

验收：任意异常任务可在 Axiom 中用 taskId 还原完整时间线；可以按供应商错误、图片大小和客户端环境切分指标。

### Batch 3 — 当前报告质量保护

目标是在不改变付费路径的前提下，确认当前 VLM 报告不会无提示地覆盖已测得的几何证据。

- 记录 VLM 脸型与 landmark `measuredShape` 是否一致，但暂不改变线上结果。
- 对高质量 landmark 与 VLM 不一致的案例建立抽样复核队列。
- 为当前报告明确“视觉分析 + 几何测量”的证据来源和不确定性文案。

验收：获得当前版本的 landmark/VLM 一致率、冲突样本和人工复核基线，为 2.0 融合规则提供输入。

## 3. Face Analysis 2.0：独立验证轨道

### 2.0-A — 规格与离线评测

- 定义融合输入、输出和状态：几何质量、几何脸型及候选项、VLM 视觉结论、融合结论、冲突原因、最终置信度。
- 使用经同意、去标识化的真人照片集和人工标注，建立各脸型准确率、混淆矩阵与拒绝策略基线。
- 报告只展示可解释依据，不要求或保存模型的隐藏推理过程。

### 2.0-B — 异步报告原型

- 提交后立即返回 landmark 基础结果；VLM 深度报告在后台任务中完成。
- 前端展示明确的“深度风格报告生成中”状态，不阻塞用户继续浏览、选框或进入试戴。
- VLM 请求保留照片与几何数据，以完成付费产品的视觉审阅价值；超时进入可恢复任务状态，而非同步重复提交。

### 2.0-C — 融合规则与内部预览

融合规则至少覆盖：

| 条件 | 2.0 行为 |
| --- | --- |
| 高质量 landmark 与 VLM 一致 | 提升最终置信度，生成完整深度报告。 |
| 高质量 landmark 与 VLM 不一致 | 显示不确定性和候选脸型；不让任一模型静默覆盖另一方。 |
| landmark 低质量、VLM 有效 | 标记为视觉估计，降低置信度并给出重拍建议。 |
| 两者均不可靠 | 拒绝输出脸型结论，指导用户拍摄更合格的照片。 |

原型仅开放给内部人员或明确标识的测试 cohort；不得与当前生产版本共用同一条提交执行链路。

## 4. 灰度替换门槛

2.0 只有同时满足以下条件才可进入小流量灰度：

- **稳定性：** 报告成功率不低于当前版本；P95 深度报告就绪时间满足既定 SLA；重复外部调用率可忽略且可证明受控。
- **质量：** 相对人工标注集，融合结果不低于当前基线；高置信度冲突有明确、可理解的用户处理方式。
- **商业：** 报告查看率、解锁率、报告后试戴率不低于当前版本；不得以降低完成率换取更丰富文案。
- **运维：** feature flag、版本化任务元数据、监控面板和一键回退均已验证。

灰度顺序：内部预览 → 小比例受控用户 → 指标稳定观察期 → 分批扩大 → 默认替换。任何阶段出现完成率、付费转化或重复调用回退时，立即回退到当前稳定版本。

## 5. 非目标

- 本轮不改变免费 Face Shape Detector 的本地隐私承诺。
- 本轮不因 2.0 试验而对同一生产用户无提示地双倍提交照片给供应商。
- 本轮不把“模型输出更长”视为“产品分析更有价值”；丰富度必须建立在可解释证据和可行动的镜框决策上。
