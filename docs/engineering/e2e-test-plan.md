# VisuTry E2E and Smoke Test Plan

## Purpose

This document defines the Phase 1 quality implementation plan for VisuTry.

The goal is not full test coverage. The goal is to protect the most important customer and merchant journeys before Merchant Pilot scale.

Principle:

> Protect business-critical flows, not every UI detail.

---

# Scope

Phase 1 includes:

1. Consumer critical flow E2E
2. Store pilot flow E2E
3. Production smoke testing

Phase 1 does not include:

- AI output quality evaluation
- Full website automation
- Multi-browser compatibility matrix
- Feature flag infrastructure
- Enterprise QA platform

---

# E2E Testing

## Consumer Critical Flow

Primary user journey:

```
Landing
  ↓
Upload Photo
  ↓
Face Analysis
  ↓
Analysis Report
  ↓
Try-On
  ↓
Credits
  ↓
Checkout
```

Initial test cases:

### Face Analysis Flow

Verify:

- Page loading
- Image upload
- Analysis task creation
- Status progression
- Report rendering

AI generation quality is not tested here.

---

### Try-On Flow

Verify:

- Frame selection
- Generation task creation
- Status polling
- Result rendering

AI provider calls should be mocked during E2E execution.

---

### Payment Flow

Verify:

- Credit consumption rules
- Checkout creation
- Payment state handling
- Webhook processing

---

# Store Pilot Flow

Merchant journey:

```
Merchant
  ↓
Merchant Session
  ↓
Recommendation
  ↓
Try-On
  ↓
Intent Capture
```

Verify:

- Merchant session creation
- Campaign/source context persistence
- Entitlement validation
- Render allowance enforcement
- Intent event creation

---

# Smoke Test

## Purpose

Confirm production availability after deployment.

Smoke tests should be fast and deterministic.

---

## Web Checks

Verify:

- Homepage returns successfully
- Main product routes are available
- Static assets load

---

## API Checks

Verify:

- Health endpoint
- Upload endpoint availability
- Generation API availability
- Authentication availability

---

## External Dependency Checks

Verify connectivity only:

- Database
- Storage
- Stripe webhook endpoint

Do not trigger paid AI generation during smoke testing.

---

# Implementation Order

## Step 1

Introduce Playwright infrastructure.

## Step 2

Implement Consumer E2E:

- Face Analysis
- Try-On

## Step 3

Implement Store E2E:

- Merchant Session
- Merchant Try-On

## Step 4

Add production smoke test.

## Step 5

Integrate with CI/CD.

---

# Success Criteria

Phase 1 is complete when:

```
Critical customer flows are automatically verified

+

Production deployments automatically verify health

+

No AI token cost is generated by routine tests
```
